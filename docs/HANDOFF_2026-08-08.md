## 2. ⚠ CRITICAL IN-FLIGHT FIX — pack/loose unit normalization (DO THIS FIRST)

**Root cause found this session:** all four line importers stored `quantity = PackQty + LooseQty/PackUnits` (pack-normalized) but `unit_price = d.rate` is the **per-piece** price. So `line_total = unit_price * quantity` understates every pack-sized line by its `PackUnits` factor. Proven: invoice 695336 line showed `0.20` vs legacy `20.00` (2 pieces × Rs.10, PackUnits=100). Invoice headers (InvTotal) are correct; only line quantities/totals/tax are wrong.

### What is already done (in working tree, uncommitted):
- `migration/cmd/bulksalelines/main.go`, `bulkpurchaselines/main.go`, `bulkreturnlines/main.go` (both SRdetail and PRdetail CROSS APPLYs): quantity formula changed to **pieces**: `PackQty * CASE WHEN PackUnits=0 THEN 1 ELSE PackUnits END + LooseQty`.
- `migration/maps/phase-e-historical-documents.json`, `phase-e-stock-ledger.json`, `phase-e-historical-reconciliation-metrics.json`, `phase-e-purchase-lines-reconciliation-metrics.json`, `phase-e-purchase-return-line-reconciliation-metrics.json`, `phase-e-sale-return-line-reconciliation-metrics.json`: same conversion applied (script: `tmp/fix-pack-expressions.ps1`).
- `services/api/internal/httpapi/reports.go`: P/O disparity query now normalizes receipt pieces back to packs via `received_quantity / NULLIF(legacy_payload->>'PackUnits', 1)` (orders stay pack-denominated).
- `migration/repair-line-units-2026-08-08.sql`: reviewed, transactional, idempotent in-place repair for `business_document_lines` (quantity, line_gross, line_total, tax_amount) and `stock_ledger` (quantity scaled to pieces). Has verification steps.
